# املاک سامی — اپ مشاور املاک (فاز ۱ تا ۴ انجام شده)

نام پکیج: `com.realestate.sami`

## فاز ۱ — پایه و منطق اصلی
✅ ساختار کامل پروژه اندروید (Kotlin + Jetpack Compose + MVVM)
✅ دیتابیس محلی Room با ۴ جدول: `Property`، `Client`، `ContactLog`، `Visit`
✅ Repository لایه برای هر دو موجودیت
✅ **موتور تطبیق خودکار دوطرفه** (`MatchingEngine`) — وقتی ملکی ثبت می‌شود متقاضیان سازگار پیدا می‌شوند و برعکس
✅ تزریق وابستگی با Hilt
✅ کار کاملاً آفلاین (بدون نیاز به اینترنت)

## فاز ۲ — تجربه کاربری کامل + طراحی مدرن + لوکال ایران
✅ **طراحی مدرن اختصاصی**: پالت سبز زمردی + طلایی گرم (نه کلیشه‌های رایج AI)، شکل‌های با سلسله‌مراتب بصری، نوار رنگی کنار هر کارت ملک بر اساس نوع معامله (خرید/اجاره/رهن/مبادله)
✅ **راست‌به‌چپ اجباری** برای کل اپ، مستقل از locale دستگاه
✅ **تاریخ شمسی** در همه‌جا (تاریخ ثبت ملک/متقاضی، تاریخچه تماس) — بدون وابستگی به کتابخانه خارجی، تبدیل مستقیم در `util/PersianDate.kt`
✅ **فرمت مبلغ به تومان**: جداکننده هزارگان فارسی، ارقام فارسی، و خلاصه‌سازی خوانا («۲ میلیارد و ۳۵۰ میلیون تومان»)
✅ همه ورودی‌های عددی فرم (متراژ، تعداد اتاق، مبلغ) هم ارقام فارسی و هم انگلیسی رو قبول می‌کنن
✅ صفحه جزئیات ملک: گالری عکس، وضعیت ملک (قابل معرفی/رزرو/فروخته‌شده/بایگانی)، **متقاضیان سازگار زنده**، تماس/پیامک مستقیم، تاریخچه پیگیری
✅ صفحه جزئیات متقاضی: معیارهای جستجو، **ملک‌های سازگار زنده**، تماس/پیامک مستقیم، تاریخچه پیگیری
✅ انتخاب چند عکس از گالری گوشی هنگام ثبت ملک
✅ آیکون اختصاصی اپ (خانه + کلید، هم‌راستا با پالت رنگی)

## دو زبانه‌سازی (فارسی/انگلیسی)
✅ تمام متن‌های اپ از `strings.xml` می‌آیند — هیچ متنی داخل کد Kotlin هارد‌کد نشده
✅ `values/strings.xml` = فارسی (پیش‌فرض)، `values-en/strings.xml` = انگلیسی
✅ اندروید بر اساس زبان سیستم گوشی خودکار انتخاب می‌کنه؛ کلیدهای دو فایل ۱۰۰٪ منطبقن (هیچ رشته جا نمونده)
✅ برای افزودن زبان سوم: کافیه یک پوشه `values-<کد زبان>` (مثلاً `values-ar` برای عربی) بسازی و همون کلیدها رو ترجمه کنی

## فاز ۳ — نقشه (تکمیل شد)
✅ نقشه گوگل (Google Maps Compose) برای انتخاب موقعیت دقیق ملک هنگام ثبت — با الگوی «پین ثابت وسط + جابه‌جایی نقشه» (مثل اسنپ/تپسی)
✅ دکمه «موقعیت فعلی من» با درخواست مجوز و FusedLocationProvider
✅ تب «نقشه» در پایین صفحه: نمایش همه ملک‌های دارای موقعیت روی یک نقشه کلی، با مارکر قابل کلیک که به جزئیات ملک می‌ره
✅ مرکز پیش‌فرض نقشه: تهران (وقتی هنوز ملکی با موقعیت ثبت نشده)

### ⚠️ قبل از اجرا: کلید Google Maps API لازمه
۱. یک پروژه در [Google Cloud Console](https://console.cloud.google.com) بساز و «Maps SDK for Android» رو فعال کن
۲. یک API Key بساز
۳. داخل `app/src/main/AndroidManifest.xml`، مقدار `YOUR_GOOGLE_MAPS_API_KEY` رو با کلید واقعی جایگزین کن
تا قبل از اون، تب نقشه به‌جای نقشه واقعی خطا/صفحه خاکستری نشون می‌ده (بقیه اپ عادی کار می‌کنه).
فونت پیش‌فرض فعلاً فونت سیستم است (که در اندروید مدرن فارسی رو خوب پشتیبانی می‌کنه). توضیح کامل فعال‌سازی فونت اختصاصی «وزیرمتن» (که برای اپ‌های فارسی توصیه می‌شه) داخل `ui/theme/Type.kt` نوشته شده — فقط کافیه فایل‌های ttf رو از فونت‌های گوگل دانلود و اضافه کنی.

## چطور بازش کنم؟
1. پروژه رو در **Android Studio (نسخه Koala یا جدیدتر)** باز کن: File → Open → پوشه `realestate_app`
2. صبر کن Gradle Sync تموم بشه (نیاز به اینترنت برای دانلود وابستگی‌ها داره)
3. برای فعال‌سازی همگام‌سازی تیمی (فاز ۴)، مراحل «راه‌اندازی در Google Cloud Console» رو پایین‌تر انجام بده. بدون این مرحله هم بقیه‌ی اپ (ثبت ملک، متقاضی، نقشه) کاملاً عادی کار می‌کنه — فقط تب «تیم» غیرفعال می‌مونه.
4. Run را روی یک شبیه‌ساز یا گوشی واقعی بزن.

## فاز ۴ — همگام‌سازی تیمی (نسخه اول انجام شد)

⚠️ **چرا Firebase نه:** Firestore و کنسول Firebase از داخل ایران بدون VPN در دسترس نیستند (تست شد: `firestore.googleapis.com` و `console.firebase.google.com` بلاک، ولی `drive.google.com` در دسترسه). به همین دلیل فاز ۴ به‌جای Firestore از **Google Drive REST API** به‌عنوان بک‌اند سبک استفاده می‌کنه — بدون نیاز به سرور اختصاصی یا VPS.

### چطور کار می‌کنه
- هر عضو تیم با حساب گوگل خودش وارد می‌شه (تب «تیم» در پایین صفحه)
- اپ یک پوشه‌ی مشترک به نام `SamiRealEstate-TeamSync` توی Drive عضو اول می‌سازه (باید این پوشه رو با بقیه‌ی اعضا به‌صورت دستی Share کنی — پایین‌تر توضیح داده شده)
- ملک‌ها و متقاضیان به‌صورت فایل JSON (`sami_properties.json`, `sami_clients.json`) داخل اون پوشه ذخیره می‌شن
- ادغام (merge) بر اساس «آخرین ویرایش برنده است» (updatedAt) انجام می‌شه، نه real-time مثل Firestore
- همگام‌سازی خودکار هر ۳۰ دقیقه (وقتی اینترنت وصله) + دکمه‌ی «همگام‌سازی الان»

### ⚠️ محدودیت‌های شناخته‌شده‌ی نسخه‌ی فعلی
- **حذف رکورد بین دستگاه‌ها sync نمی‌شه** — اگه یک مشاور ملکی رو حذف کنه، روی گوشی بقیه هنوز هست (برای رفع این، باید فیلد `isDeleted` به entity ها اضافه بشه — کار فاز بعدیه)
- فقط **ملک‌ها و متقاضیان** sync می‌شن؛ تاریخچه‌ی تماس و بازدیدها هنوز نه
- عکس‌های ملک هنوز فقط محلی هستن (روی Drive آپلود نمی‌شن) — قدم بعدی
- این real-time نیست؛ تأخیر تا ۳۰ دقیقه (یا دستی با دکمه‌ی Sync) طبیعیه

### راه‌اندازی در Google Cloud Console (یک‌بار، قبل از اجرا)
۱. یک پروژه در [Google Cloud Console](https://console.cloud.google.com) بساز (یا همون پروژه‌ی نقشه رو استفاده کن)
۲. از منوی APIs & Services → Library، «Google Drive API» رو فعال کن
۳. از OAuth consent screen: نوع رو **External** بذار و در حالت **Testing** نگهش دار (نیازی به تایید گوگل نیست چون فقط ۲ تا ۵ نفر ازش استفاده می‌کنن)
   - ایمیل جیمیل هر عضو تیم رو به‌عنوان **Test user** اضافه کن، وگرنه login‌شون fail می‌شه
۴. از Credentials → Create Credentials → OAuth client ID:
   - نوع: **Android**
   - Package name: `com.realestate.sami`
   - SHA-1 fingerprint: با `./gradlew signingReport` بگیر (هم نسخه‌ی debug هم release رو اضافه کن)
۵. نیازی به دانلود فایلی نیست (بر خلاف Firebase) — همین که client ID ساخته بشه کافیه، چون از GoogleSignInClient استاندارد استفاده می‌کنیم

### اشتراک‌گذاری پوشه‌ی تیمی با بقیه‌ی اعضا
بعد از این‌که نفر اول (مثلاً مدیر دفتر) یک‌بار sync کرد، پوشه‌ی `SamiRealEstate-TeamSync` توی Drive خودش ساخته می‌شه. باید:
1. وارد drive.google.com بشه
2. روی پوشه راست‌کلیک → Share → ایمیل بقیه‌ی مشاوران رو با نقش **Editor** اضافه کنه
3. بقیه‌ی اعضا هم داخل اپ وارد همون حساب گوگل بشن و «همگام‌سازی الان» رو بزنن

## فاز ۵ — یادآوری، تقویم و گزارش‌گیری (انجام شد)

✅ **بازدید + تقویم سیستم**: در صفحه جزئیات ملک و صفحه جزئیات متقاضی، بخش «بازدیدها» اضافه شد.
از بین متقاضیان/ملک‌های سازگار، یکی را انتخاب و تاریخ/ساعت بازدید را مشخص می‌کنی؛ رکورد در
`VisitEntity` ذخیره می‌شود و با دکمه‌ی تقویم، رویداد از قبل پرشده به برنامه‌ی تقویم پیش‌فرض گوشی
فرستاده می‌شود (`ACTION_INSERT` روی `CalendarContract` — بدون نیاز به مجوز READ/WRITE_CALENDAR،
دقیقاً مثل تماس مستقیم که در فازهای قبل استفاده شده). نتیجه‌ی هر بازدید (در انتظار/علاقه‌مند/
بی‌علاقه/معامله موفق) هم از همان بخش قابل ثبت است.

✅ **نوتیفیکیشن پیگیری**: هر ۶ ساعت یک Worker (`FollowUpReminderWorker`) بررسی می‌کند که آیا
`followUpDate` ثبت‌شده روی یک `ContactLogEntity` فرا رسیده؛ اگر بله، نوتیفیکیشن محلی نمایش
می‌دهد (بدون نیاز به اینترنت یا سرور). موعد پیگیری از طریق چیپ‌های سریع «فردا / ۳ روز دیگر /
هفته دیگر» در فرم افزودن یادداشت تماس تعیین می‌شود. از اندروید ۱۳ به بعد، مجوز نوتیفیکیشن یک‌بار
در اولین اجرا درخواست می‌شود.

✅ **خروجی PDF/Excel از لیست ملک‌ها**: از دکمه‌ی خروجی در بالای لیست ملک‌ها (یا صفحه‌ی گزارش‌ها)
قابل دسترسه. هر دو فرمت بدون هیچ وابستگی سنگین (بدون Apache POI که روی اندروید مشکل‌ساز است)
تولید می‌شوند — PDF با `android.graphics.pdf.PdfDocument` و Excel با یک نویسنده‌ی سبک XLSX
دست‌ساز (`XlsxWriter`) — و با Intent اشتراک‌گذاری به هر اپ (واتس‌اپ/ایمیل/تلگرام) فرستاده می‌شوند.

✅ **داشبورد آماری** (تب «گزارش‌ها»): تعداد کل ملک‌ها، ملک‌های قابل معرفی، معاملات موفق، متقاضیان
فعال، بازدیدهای پیش‌رو، و برآورد درآمد کمیسیون (بر اساس نرخ کمیسیونی که خودت وارد می‌کنی — چون
این نرخ بین دفترها فرق می‌کند، فقط روی همین گوشی ذخیره می‌شود، sync نمی‌شود).

### ⚠️ محدودیت‌های شناخته‌شده‌ی فاز ۵
- انتخاب تاریخ/ساعت بازدید از `DatePickerDialog`/`TimePickerDialog` استاندارد اندروید است که
  میلادی است (تقویم انتخاب‌گر شمسی اختصاصی هنوز پیاده نشده)؛ بعد از انتخاب، همه‌جای اپ تاریخ را
  شمسی نشان می‌دهد.
- نوتیفیکیشن پیگیری فقط محلی روی همین گوشی کار می‌کند و بین اعضای تیم sync نمی‌شود (چون
  sync تاریخچه‌ی تماس هنوز در فاز ۴.۱ نیست).
- برآورد کمیسیون ساده است: برای معامله‌ی رهن کامل مبلغ ودیعه و برای اجاره فقط اجاره‌ی یک ماه
  در نظر گرفته می‌شود؛ برای محاسبه‌ی دقیق‌تر (مثلاً کمیسیون بر مبنای اجاره سالانه) باید فرمول
  در `ReportsViewModel.commissionableAmount()` دستی تنظیم شود.
- ردیف «بازدیدهای پیش‌رو» در داشبورد فعلاً فقط شناسه‌ی عددی ملک/متقاضی را نشان می‌دهد نه نام؛
  برای نمایش نام واقعی باید یک join ساده به Property/Client اضافه شود (بهبود کوچک بعدی).

## نقشه راه فازهای بعدی (به ترتیب اولویت)

### فاز ۴.۱ — تکمیل همگام‌سازی
- افزودن `isDeleted` (soft delete) برای sync شدن حذف‌ها

## نکته مهم درباره ساخت واقعی APK
این محیط (چت) امکان نصب Android SDK و کامپایل واقعی رو نداره؛ کدها استاندارد و کامل نوشته شدن و باید مستقیم در Android Studio بدون مشکل ساخته بشن. اگه هنگام Sync یا Build با خطایی مواجه شدی (مثلاً به‌خاطر آپدیت نسخه پلاگین‌ها)، همون خطا رو برام بفرست تا اصلاحش کنم.
